# Схема локального хранения

Приложение и widget extension используют `companion.sqlite` в общем контейнере. Единственная строка содержит версию формата и UTF-8 JSON модели `Companion`. SQL-контракт задаёт [Store](../Shared/Store.swift).

```sql
CREATE TABLE snapshot (
    id INTEGER PRIMARY KEY CHECK(id=1),
    version INTEGER NOT NULL,
    body BLOB NOT NULL
)
```

Чтение поддерживает версии 1 и 2. Декодер восстанавливает отсутствующие новые поля значениями по умолчанию и сопоставляет старую реплику с героем. Следующая успешная запись сохраняет версию 2. В JSON входят выбранный герой, настройки поведения, контакты, история и состояние каждого героя, находки, локальные задачи, календарный снимок и журналы согласования уведомлений. Описания полей находятся рядом с [моделью](../Shared/Companion.swift), [журналом личных уведомлений](../Shared/CompanionNoticePlan.swift) и [календарным журналом](../Shared/CalendarSnapshot.swift).

`readIfPresent` открывает БД только для чтения и возвращает `nil`, когда отсутствует файл или строка. `read` в этом случае возвращает начальное состояние приложения. Повреждённый JSON, неизвестная версия и конфликт блокировки передаются вызывающей стороне как ошибки.

`update` может создать БД при первом сохранении. Оба пути записи используют `BEGIN IMMEDIATE`, перечитывают состояние под блокировкой и выполняют `COMMIT` после сериализации. Время ожидания занятой БД ограничено 250 мс. `updateIfPresent` у интерактивного виджета требует существующей строки и позволяет отклонить устаревшее действие без записи. При выходе из незавершённой транзакции выполняется откат. [Решение о хранении](ADR/0001-storage-and-refresh.md) · [Регрессии SQLite](../Tests/StoreTests.swift)

App Group UserDefaults публикует политику приватности календаря для виджета. Настройки интерфейса также используют UserDefaults приложения. Создание новых БД на iOS запрашивает защиту до первой разблокировки. Фактическое поведение до и после разблокировки проверяется на устройстве. [Безопасность](SECURITY.md)
