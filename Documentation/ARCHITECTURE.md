# Архитектура приложения и виджета

Приложение и расширение собирают общие исходники из Shared. Companion задаёт переходы состояния. Store принимает URL базы, а точки входа используют контейнер общей группы. SwiftUI отображает последний снимок. AppIntent выполняет короткую транзакцию без запуска приложения. Тестовая локальная нотификация создаётся по явному действию и имеет постоянный идентификатор для отмены.

Шесть встроенных пакетов содержат по 150 реплик и пять открываемых находок. App, Widget и SwiftPM используют один каталог Shared/Characters. Выбор героя и история последних ID каждого персонажа входят в общий снимок v2. При первой записи старый снимок v1 преобразуется с сохранением режима и текущей реплики Годжо. Чтение сцены не обновляет историю. Интерактивный выбор исключает последние 15 ID. В Normal дневное нажатие имеет один шанс из 12 открыть новую находку, с общим интервалом минимум шесть часов. DayTimeline строит пассивные кадры по локальному часу. Ночью сцена молчит до контакта. Разовое утреннее приветствие хранится по герою и локальной дате. Предварительный расчёт кадров не обновляет отметку контакта. Контекстные записи используются при изменении расписания и обработке локальных задач.

Приложение читает EventKit по явному разрешению и публикует ограниченный [календарный снимок](CALENDAR_INTEGRATION.md). Виджет фильтрует его по настройкам приватности. [Планировщики уведомлений](NOTIFICATION_SYSTEM.md) сравнивают желаемые запросы с очередью iOS. Резервы и подтверждения записываются через транзакции общего [хранилища](STORAGE_SCHEMA.md).

[Система персонажей](CHARACTER_SYSTEM.md) описывает связи между событиями, состоянием, репликами и находками. [Бюджеты ресурсов](PERFORMANCE.md) применяются при декодировании арта и построении timeline.
